# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

Data mirror for the MOE 《臺灣客語辭典》 (https://hakkadict.moe.edu.tw/). The repo downloads upstream `.ods` sources for all six dialects (四縣腔 / 南四縣腔 / 海陸腔 / 大埔腔 / 饒平腔 / 詔安腔), and publishes:

- Original `.ods` files for **all six** dialects under `public/<version>/tangloo/` — raw mirror.
- Merged `.csv` + `.json` under `public/<version>/bunji/` containing **only Si-yen + Nam-si-yen** (with a `Dialect` column). The other four dialects are intentionally not merged: they have no PFS conversion mapping and are kept as raw ODS only.
- `public/manifest.json` pointing at the latest version (lists all six ODS files plus the merged CSV/JSON).

Dialect lists live in `build_mirror.py`: `PROCESSED_DIALECTS` (read + merged + PFS-converted) and `EXTRA_DIALECTS` (downloaded only). To promote an extra dialect into the merged set, move it into `PROCESSED_DIALECTS` and add a `KPPY_PITCH_TO_INTERNAL` entry for it.

Distribution is via GitHub Pages — the URLs in `README.md` (`thoivanhakfa.github.io/HakkaDictMoeDataMirror/...`) are the public consumer interface, so existing column names and file paths are part of the contract.

## Build

Requires Python 3, Node.js, and JDK 17+ (for building KonvertToPFS).

```bash
# One-time: build the KonvertToPFS JS library
cd lib/KonvertToPFS && ./gradlew :lib:jsNodeProductionLibraryDistribution && cd ../..

# Run the build
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python script/python/build_mirror.py          # downloads fresh ODS
python script/python/build_mirror.py --reuse-ods  # reuse from latest version
```

`build_mirror.py` is the entire build. Each invocation:

1. Stamps a new `version_id = YYYYMMDD-HHMM` and creates `public/<version>/{tangloo,bunji}/`.
2. Downloads both ODS files fresh from `hakkadict.moe.edu.tw` (or copies from latest version with `--reuse-ods`).
3. Reads them with pandas (`engine="odf"`), prepends a `Dialect` column, concatenates, strips column whitespace, drops `Unnamed:*` columns.
4. Adds `音讀（符號）` immediately after `音讀` via `reading_digit_to_symbol(reading, dialect)` (see below).
5. Converts `音讀` (KPPY 數字式) → KPPY_INPUT (internal digits) → PFS via [KonvertToPFS](https://github.com/Phakfasu/KonvertToPFS) (`lib/KonvertToPFS`, Git submodule). Adds `PFS` (PFS Unicode) and `PFS輸入式` (PFS Input) columns. The conversion is batch: Python maps Chao pitch values to KPPY_INPUT digits via `KPPY_PITCH_TO_INTERNAL`, then pipes all readings through `script/js/convert_to_pfs.js` which calls the KonvertToPFS JS library.
6. Writes merged CSV + JSON, rewrites `public/manifest.json`, and rewrites the **Version ID / Last Updated / download paths** in `README.md` via regex.

There is no test suite, no linter, and no CI. The build is idempotent only in the sense that re-running creates a *new* timestamped version; older `public/<version>/` directories are kept.

## Phonetic-reading conversion

The `音讀` column from the upstream ODS is in **KPPY 數字式** form (Chao pitch values). The build derives three additional columns:

1. **`音讀（符號）`** (KPPY 符號式 / 調型) — via `reading_digit_to_symbol()` in Python. Mapping lives in `TONE_DIGIT_TO_SYMBOL`, keyed by `Dialect`.
2. **`PFS`** (PFS Unicode) — via KonvertToPFS. KPPY 數字式 is first mapped to KPPY_INPUT (internal digits 1–6 via `KPPY_PITCH_TO_INTERNAL`), then converted by KonvertToPFS to PFS_UNICODE.
3. **`PFS輸入式`** (PFS Input) — via KonvertToPFS, same pipeline as above but outputting PFS_INPUT.

Notes:
- Only Si-yen / Nam-si-yen are exercised by the current upstream sources; `TONE_DIGIT_TO_SYMBOL` keeps entries for other dialects in case more ODS files are added. `KPPY_PITCH_TO_INTERNAL` currently covers Si-yen / Nam-si-yen only.
- 入聲 syllables retain their stop coda (`-b`/`-d`/`-g` in KPPY; `-p`/`-t`/`-k` in PFS); the KPPY symbol attaches *after* the coda.
- Unknown pitch digits fall through unchanged (the converter does not raise) so source anomalies stay visible in the output rather than being silently dropped.
- KonvertToPFS uses PFS-aligned tone numbering (1–6) internally. `音讀（符號）` is generated by the Python mapping in `TONE_DIGIT_TO_SYMBOL` (not by KonvertToPFS) because it operates directly on the KPPY 調值 digits from the upstream ODS.

If you change column names, update both `build_mirror.py` and the README mapping table; if you change the mapping, the README table is the user-visible spec and must be kept in sync.

## Conventions

- **Terminology** (mirrors README and global preferences): use **Si-yen** and **Nam-si-yen** in English text. Avoid "Sixian" / "South Sixian".
- **`.gitignore`** allows `*.ods` only under `public/**/`. Do not commit ODS files anywhere else; the upstream copies under `public/<version>/tangloo/` are intentionally tracked because they are part of the published mirror.
- **Only the latest `public/<version>/` directory is kept.** When a new build is published, the previous version directory is pruned from the working tree before the next commit. The build script itself does **not** delete prior versions — that's a separate step (manual `rm -rf` or external tooling). Git history is not an archive — it gets squashed periodically, so older snapshots are only recoverable from the upstream MOE site. The currently-published version directory is the one referenced by `public/manifest.json` and the README download links.
- **README is partially generated.** The "Version ID", "Last Updated", and `public/<version>/` URLs are rewritten by `update_documentation()` on each build. Hand edits to those specific fields will be overwritten next run; edit the surrounding prose freely.
